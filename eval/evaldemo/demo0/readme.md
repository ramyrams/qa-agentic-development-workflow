Two real options, and I built and verified one of them for you before answering.

**If you want a maintained, purpose-built framework:** Promptfoo is completely free and open source under the MIT license, with no paid tier or usage limit — you only pay for the API calls to whichever LLM provider you configure. Its promptfoo view command renders results as a grid where rows are test cases and columns are configuration variants, with each cell showing the actual output and whether it passed — genuinely well-suited to exactly the with-skill/without-skill comparison your eval methodology already does. One thing worth knowing given your governance role rather than burying it: OpenAI announced it is acquiring Promptfoo in March 2026, and the future of the open-source project post-acquisition hasn't been clarified, though the codebase remains open source and all model provider integrations, including Anthropic's, are currently unchanged. Functionally fine today; worth a line in your vendor-risk notes if you adopt it, since the honest answer on long-term neutrality is "currently yes, not guaranteed." The real cost of adopting it isn't the license — it's migrating your evals.json-shaped test cases into Promptfoo's own YAML config format. [Pristren + 3](https://pristren.com/blog/promptfoo-eval-tool-guide/)

**If you'd rather not adopt a new tool at all**, I built you a zero-dependency alternative — pure Python standard library, nothing to install, nothing to license, and it works directly with the grading.json-shaped data your eval runs already produce. I generated a real report from the actual verified results of the csv-analyzer demo (7/7 assertions passed across both cases) and rendered it to an image to confirm the HTML/CSS actually displays correctly before handing it to you — report--sample-output.html is that real, verified output, and report--generate\_report.py is the generator itself: point it at any report-data.json shaped like the sample and it produces a clean page with a summary card row (cases, passed, failed, pass rate), then one card per test case showing the prompt, expected output, and a color-coded assertion table with evidence.

My honest recommendation given where you are: use the script I just built for now — it costs nothing to adopt since it already speaks your data format, and it's genuinely readable (open report--sample-output.html in any browser to see for yourself). Revisit Promptfoo specifically if your eval program grows to the point where you want multi-model comparison, built-in red-teaming, or a maintained tool with an ecosystem behind it — that's a real future upgrade path, not a wrong choice today, just a bigger commitment than your current scale needs.
